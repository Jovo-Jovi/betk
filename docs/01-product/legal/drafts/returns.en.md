# Return and refund policy

These pages describe how the marketplace behaves. Blanks in square brackets are for counsel. They are not filled in here.

This is the platform policy. A shop can also store its own return text. How the two texts relate is not decided. This draft does not rank them.

<!-- cite: UI P69; REG-85 as an open product choice, not a decision -->

## 1. When a buyer can ask

<!-- cite: PRD R-U01, R-U02 -->

The buyer can request a return on a seller order that has been delivered, with a reason and evidence. Evidence is stored in its own table. It is not the dispute-evidence collection.

The request is refused while the return window is empty or not a positive whole number. The window is [PIN: return_window_hours]. It does not fall back to the payout hold.

<!-- cite: plan §8.2.5 -->

## 2. What happens next

<!-- cite: PRD R-U03, R-U04, R-U05 -->

If the seller accepts, the path is return and then refund. If the seller rejects, the path is a dispute and then a staff decision.

The refund may be all or part of that seller order. The goods portion is stored on the seller order. Any delivery-fee portion stays on the payment row. The seller sees the goods portion only.

Stock is not put back automatically when an item is returned.

## 3. The deposit

<!-- cite: PRD R-O16; baseline §2.4; PRD R-O22, R-O23, R-O24; baseline §2.6 -->

The first payment is 50% of (goods subtotal + delivery), paid to BETK. After staff confirm it, the buyer cannot cancel. The exit is this return path, a refund, or a dispute.

If staff reject the transfer screenshot, the order is cancelled, stock is restored, and a refund is triggered if the transfer was taken.

A cancellation that happens after a confirmed deposit triggers a refund.

The payout to the seller waits until delivery plus [PIN: return_hold_hours]. That hold is not the return window.

<!-- cite: PRD R-O29; ERD §6.2 -->

## 4. Acceptance

<!-- cite: PRD R-G05, R-G06; ERD §6.1 -->

The public page can be read without an account. Whether completing an order requires an acceptance of this policy is not decided. If it is included, the version label is [PIN: agreement_return_policy_version], and a new version needs a new acceptance. An empty version is not treated as “skip this document”.
