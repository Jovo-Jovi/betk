# PRECEDENTS.md
> Compact catalogue of recurring architectural/procedural patterns established across BETK's build so far. Consult this BEFORE re-deriving a pattern from scratch — cite the precedent, don't reinvent it. Full narrative detail for every instance lives in `docs/12-changelog/DEVELOPMENT_JOURNAL.md`. Append new rows here as new precedents are established; never delete a row (mark superseded in-place if a pattern changes).

| Precedent | Rule (one line) | Established / instances |
|---|---|---|
| **BL-01-FIX class (hard-404 status)** | No `loading.tsx` may sit at or above any route segment whose `page.tsx` can (transitively) reach `notFound()` — an ancestor Suspense boundary commits HTTP 200 at first flush before the awaited `null`→`notFound()` can set 404. Fix = DELETE the offending `loading.tsx`, never add one. | BL-01-FIX (`[locale]/loading.tsx`, 2026-07-02) · Phase-03/T04 (`(public)/loading.tsx`) · Phase-06/REG-46 (`(buyer)/loading.tsx`). **Guard E = REG-47** (open, record-only) — a committed CI check for this class is owed. |
| **File-path Server-Action/query imports** | Client components import feature actions/queries by their exact file path, never via the feature barrel — the barrel also re-exports `next/headers`-backed queries, which would leak a server-only import into a client bundle. | Phase-04/T04 onward (`StoreProfileForm`, `OnboardingWizard`, listings/messaging actions) — now the default pattern for every feature. |
| **Pre-checks are UX-only; DB constraints are authoritative** | A client-/server-side pre-check (slug availability, dup-application, etc.) is best-effort UX only; the real guard is the DB constraint (23505 unique violation) mapped to a typed error. Never trust the pre-check as the security boundary. **B4-FIX:** withholding a column on a seller page is not a boundary when that role’s grants include the column. The seller-readable refund column was redefined (`refunded_subtotal`) so the value the grant returns is fee-free. | Phase-04/T03 (seller application slug), T04 (onboarding slug), T06 (`R-S03` slug change-once), Phase-05 (listing slug/tag/image limits). Instance: B4-FIX (2026-09-22) — `BETK_ERD.md` §3.10. |
| **The #14 RLS class — ERD-specced-but-absent policy** | When a table's RLS policy is specced in `BETK_ERD.md §3` but the live `pg_policies` shows it absent (RLS-enabled, zero-policy → default-deny), mint a new REG-#, close it with ONE additive migration that adds exactly the specced policy, and never broaden beyond the ERD row's text. | open-issue #14 (catalog, 2026-07-01) → REG-29 (`store_follows`) → REG-31 (`stores` INSERT) → REG-34 (listing children) → REG-41 (inquiries/inquiry_messages). Owning-phase map: `SESSION_CONTEXT.md` ERD §3 table. |
| **REG-24 migration procedure** | Every migration: MCP `apply_migration` (direct CLI is blocked, no creds) → rename the local file to match the applied version exactly → confirm ledger 1:1 remote↔local → backfill `BETK_DATABASE_SCHEMA.sql` → run the advisor sweep and diff against the STATED baseline (0 new / explain every new finding). | Every migration since R1 (2026-07-16) — R2/R3, Phase 04/05/06 migrations, REG-24 itself. |
| **Ledger-repair by file-forward-port** | When staging already has an applied version that `main`'s local `supabase/migrations` lacks (applied on an unmerged feature branch), restore 1:1 by copying the **file blob** from the preservation tag onto main — live-MATCHES-FILE first, then `git checkout <tag> -- <path>`, prove byte-identity (`git hash-object` == `git rev-parse tag:path`), filename = `{applied version}_{applied name}.sql`. **Never** `apply_migration` / never rewrite the SQL / never bring `src/` with it. Inverse of REG-24 (which is apply-then-rename). | Stage A-RESUME (2026-09-19) — `20260723140552_order_payment_write_layer_reg49.sql` from `archive/phase-07-v1-single-seller` (blob `06238da9332dafd822aa057f42ab7fdfa400c561`). |
| **REG-32 rpc typegen** | `betk`-schema RPC signatures are CI-generated, never hand-maintained. If `types-drift` fails on a hand-edit, pull the CI job's printed diff and apply it to `types.ts` VERBATIM (byte-identical). Any resulting non-null-`Args` breakage at a call site gets ONE documented boundary cast — never re-edit the generated file. | REG-32 (Phase-04/T08-FIX, 2026-07-20) — `submit_seller_application`/`resubmit_seller_application` signatures. |
| **REG-19 — `betk.users` writes stay service-role** | No scoped self-UPDATE RLS policy exists for `betk.users` (the table-level `authenticated` UPDATE grant covers ALL columns, so any `USING(id=auth.uid())` policy would be a privilege-escalation vector until that grant is column-re-scoped). All `betk.users` writes (`last_login_at`, `deleted_at`, `phone_number`, role flips) go through a service-role helper. Standing — revisit only deliberately. | T02 (`last_login_at`) · T06 (`deactivateAccount`) · T07 (`setUserPhoneNumber`) · Phase-04/T03 (`setUserRole`). |
| **REG-40 — explicit locale threading on ISR** | On any ISR route under `[locale]` whose `generateStaticParams` returns `[]`, thread `locale` EXPLICITLY on every render path (`getTranslations({locale})`, `locale` prop into Suspense-wrapped children, `locale=` on server `<Link>`) — next-intl's `setRequestLocale` cache-store is not reliably resolved on the on-demand/non-default-locale path (symptom: 500 on `/en/…`, 200 on `/…`). | PERF-02 (2026-07-21) — `/category/[slug]`, `/listing/[id]`. Full rule: `docs/02-architecture/CACHING_STRATEGY.md §7`. |
| **REG-42 — column-grant pattern** | Row-scoped RLS (`USING`/`WITH CHECK`) cannot confine WHICH COLUMNS a policy's command may touch, and `WITH CHECK` cannot see the pre-update (`OLD`) row — so a "receiver may flip only this one column" requirement needs a `REVOKE`+`GRANT UPDATE(column)` (privilege-level column confinement) COMBINED with a row-scoping policy, not a policy alone. | REG-42 (Phase-06/T02-FIX, 2026-07-22) — `inquiry_messages.is_read` receiver-writable, `body` still denied by the grant (42501). |
| **Throwaway-smoke pattern** | Runtime/E2E proof against real staging without a permanent test fixture: mint real GoTrue users via the admin/service client, forge a real `@supabase/ssr` session cookie using the library's OWN serialization helpers (never hand-rolled), drive it over HTTP against a local `next start`, then DELETE everything before commit and re-query to confirm zero residue. **Interrupt-fragility caveat (REG-71):** teardown that runs in `afterAll`/a trailing DELETE is SKIPPED when the run is interrupted (Ctrl-C/stop/timeout/crash), so an interrupted run leaks its FULL fixture footprint into shared staging — `purge()` being correct is necessary but NOT sufficient, it must actually RUN. Mitigation = an operator sweep (RESIDUE-PURGE) + a suite-START residue detector (Guard G = REG-74); a mid-suite whole-table canary catches it late, a front-door pre-flight catches it early. | Phase-04/T05, T08 onward · Phase-05/T04, T05, T06 · Phase-06/T01–T05 · RESIDUE-PURGE (2026-07-24) swept 64 orders + full footprint from 4 interrupted-run batches (71→7); the 7 `order_status_history`-bearing orders are the sole undeletable residue class. |
| **Hydration-payload false-positive (test-methodology, not a product bug)** | A blanket `html.includes(...)`/`.Contains(...)` check for a translated string is unreliable — next-intl's client provider inlines the WHOLE active namespace's JSON into the hydration payload for any client component in scope, so the raw string can appear even when nothing renders it. Scope the assertion to the actual DOM element instead. | Phase-03/T07 (`.Contains`) · Phase-06/T04 (`html.includes()`). |
| **Compose-only / Claude-Design ownership** | `components/ui` + `components/shared` are OWNED by Claude Design; Cursor composes + wires data, NEVER restyles. Any shared-kit defect found while composing gets flagged/routed through Claude Design (a CD-DELTA), never patched directly by the composing task. | Every feature task since Phase 03; CD-DELTA-1..4 land cycle. |
| **STOP-and-flag on frozen scope / unpinned facts** | If a task would require inventing a page/table/feature outside the frozen MVP scope, or a schema/behavior fact is not citable from a source doc or live introspection, STOP and flag it (mint a REG-# or record it as an open decision) rather than improvising. | OD-1..7 frozen decisions · REG-23 (design-repo pointer) · REG-26 (`view_count` mechanism) · every "cite-or-flag" instance below. |
| **Guidance-only dead-link rule** | A CTA/link to a not-yet-built same-phase route is an expected forward reference (not a "dead link"); a CTA to an out-of-scope/later-phase surface is either omitted or rendered disabled-with-a-stated-reason — never a fabricated route. | Phase-05/T03 (`/seller/listings/new` before T04 existed) · Phase-06/T03 (confirmed-status banner, no `/checkout` link, Phase-07 owns it). **SUPERSEDED (B7):** “Phase-07 owns it” is the retired checkout phase. v2 checkout is Phase 11. The dead-link rule itself holds. |
| **Cite-or-flag on every schema fact** | Every schema/enum/trigger/policy fact used to justify a decision is cited from `BETK_DATABASE_SCHEMA.sql` + live introspection (`pg_enum`/`pg_policies`/`pg_trigger`/`pg_proc`/`information_schema`), never assumed. If a fact is genuinely unpinned anywhere, that itself is flagged (mint a REG-#), not silently invented. | Every pinned CONTRACT block (e.g. Phase-06/T01's CONFIRM→CHECKOUT CONTRACT) · REG-26/REG-33/REG-43 (mechanism-unpinned flags). |
| **Advisor-baseline discipline** | The security-advisor sweep's baseline (rls-no-policy INFO / search_path WARN / extension WARN / sec-definer-exec WARN / leaked-password WARN counts) is STATED at the start of every migration-touching task and RE-STATED after applying — 0 unexplained new findings is the bar, and a resolved finding should visibly move the count. | Every migration since R1; current baseline recorded in `SESSION_CONTEXT.md` Standing facts. |
| **No off-platform contact affordances** | All buyer↔seller communication is in-app. A doc/UI line naming an external channel is a **share** (channel-agnostic device share sheet on a public link), a **BETK→user notification** (OD-5 WhatsApp templates), or **BETK support** (a BETK→user support channel) — **never counterparty contact**. **SUPERSEDED (v1, not deleted):** Identity/address cross only via the courier/shipping label (REG-14: `delivery` mode covers self-delivery, so a self-delivering seller IS the courier and reads the label). **v2 operative (OD-10, OD-17, N28):** the seller sees **no buyer identity and no buyer location** (not name, not phone, not address, not city); the BETK-generated label is admin + courier only. Courier principal for RLS = REG-78 (B3). | Established: REG-45 misread (2026-07-23, CORRECTION-02) — buyer/seller inbox WhatsApp deep-links deleted; REG-50 (support) + REG-51 (share) are the allowed external-channel exceptions. Self-delivery-as-courier clause superseded in place by B1 / B1-FIX (2026-09-19). |
| **Three-layer actor↔column write control** | A custodial/multi-actor UPDATE path (different actors may touch different columns, and legality depends on the *transition* `OLD→NEW`) is secured with THREE cooperating layers, never one: **(1) column GRANT** — `REVOKE UPDATE … ; GRANT UPDATE(col,…)` bounds WHICH columns each role may write (a forbidden column → error 42501, not a silent no-op); **(2) row policy** (`USING`/`WITH CHECK`) bounds WHICH rows; **(3) an OLD-aware `BEFORE` trigger** (search_path-pinned + `EXECUTE` revoked) enforces transition legality + server-stamps derived/actor columns (`WITH CHECK` can't see `OLD`, so legality is not RLS-expressible). Ungranted-but-server-set columns (e.g. `confirmed_at`, `cancelled_by`) are stamped by the trigger, never by the client. Keep `is_admin()` in the POLICY for read/row access but out of the trigger's actor checks when a later phase owns the admin-forced transition. | ADR-019 / REG-49 (Phase-07/T02b, 2026-07-23) — `orders`/`payments` UPDATE (`enforce_order_transition`/`enforce_payment_update` + column grants + `orders_update`/`payments_update`). Builds on the REG-42 column-grant pattern (adds the OLD-aware trigger leg). **SUPERSEDED instance (B7):** that Phase-07/T02b landing shipped `create_order_from_inquiry` and the AC-SEL-14 seller-acceptance gate. The three-layer pattern holds (baseline §11). The establishing instance is archived. Successor: ADR-025 reworks the transition in Phase 08; Phase 13’s exit is the refusal test for retired seller acceptance. Stock no longer decrements on seller confirm (`decrement_stock_on_confirm` is detached by ADR-025; OD-15 decrements at checkout). No PRECEDENTS row named the flat delivery fee; that mechanic is retired under OD-10, and REG-65 (open, Phase 09) is the onboarding field that still stores it. |

| **No courier RLS principal** | A fulfilment participant who must see buyer name, phone, and address, and who is forbidden from having a login (AC-COU-6), is not an `auth.uid()` role and is not an RLS policy. **B5 (ADR-024) recorded both branches and did not pick.** Admin-initiated handoff = the admin’s own RLS read. No `SECURITY DEFINER`. No service role. Automated handoff with no admin session = a server-side service-role read, still no definer. The mechanism stays under the courier gate (REG-78). Shipment status writes stay admin. | B3 (2026-09-22), revised B3-FIX, confirmed B5 — REG-78, ADR-024, `BETK_ERD.md` §3.1. |
| **Hide a stored column from the whole `authenticated` role** | When no `authenticated` reader needs a stored column, and admin is that same role, revoke table-level SELECT from `authenticated` and `anon`, then grant SELECT of every other column to `authenticated`. A column revoke does nothing while the table grant exists (REG-42 shape, applied to SELECT). The hidden columns stay stored. `select *` and `RETURNING *` raise 42501. A column added later is invisible until granted. | B5 (2026-09-22) — ADR-020, REG-90, guard REG-92. `seller_orders.delivery_fee` and `total_amount`. |
| **A retired phase number is never reused** | A phase number that names an archived build stays a hole in the integer sequence. A later plan takes the next integer after the hole and prefixes the unbuilt historical headings so one number cannot mean two plans. | B6 (2026-09-22) — Phase 07, tag `archive/phase-07-v1-single-seller`. v2 execution is 08–20. |
| **A column-grant guard is not a typecheck** | Generated `Row` types still list columns whose SELECT was revoked, so `select *` typechecks and Postgres raises 42501 at runtime. The guard is a lint or a runtime test. It is not `tsc` and it is not types-drift. | B6 (2026-09-22) — REG-92, scheduled on Phase 08 with the ADR-020 grant. |
| **Legal-gate artefacts are questions, not findings** | A legal-gate pack states product facts with citations and asks counsel questions. It does not state that a design meets a rule, and it does not resolve a frozen scope risk. | E-1 (2026-09-23) — `docs/01-product/legal/E1_LEGAL_GATE_PACK.md`, `COUNSEL_BRIEF.md`. |
| **Forbidden data has no slot** | A component that must never show a value has no prop for it — not a hidden prop and not an optional prop. | D-1 (2026-09-25) — UI spec §8 (“a slot that exists will get filled”); `docs/00-design/CD_DELTA_6_HANDOFF.md` SellerOrderMoney (no delivery fee, no order total). |
